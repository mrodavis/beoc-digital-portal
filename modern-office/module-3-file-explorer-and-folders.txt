## Organization is a decision made once
 type: scenario
 role: You inherit the shared drive at Lakeside Medical Associates.
 text: It contains 1,400 files across four levels of folders. Names include 'letter final.docx', 'letter final v2.docx', 'letter FINAL USE THIS.docx', and 'Copy of Copy of intake form.docx'. Nobody can find anything, so people save new copies rather than search — which makes it worse every week.
 task: Design a structure and naming convention that stays usable as it grows.

Folder structure should mirror how people look for things, not how they were created. Most offices organize by function, then by year, then by type — because that is the order someone actually thinks in when searching: what kind of thing, from when.

Naming matters as much as structure, because search only works if names are predictable. A good file name contains the date in year-month-day order, a description, and a version if versions matter.

    'Final' is not a version; a number and a status is

Note: Year-first dates — 2026-09-01 rather than 09-01-2026 — are the single highest-value naming habit. They sort chronologically in every file list automatically, with no effort and no special tooling. Once you have used them for a month, the alternative starts to look broken.

Check yourself: Why should dates in file names be written as 2026-09-01 rather than 09-01-2026? Answer: Year-first dates sort chronologically when files are sorted by name. Sorting a file list by name puts year-first dates in true chronological order automatically, because the most significant digits come first. Month-first dates group every January together across all years, which is almost never what you want.
